## Why

`src/bridge-client.ts` 已 560 行 / 36 个方法, 超出项目 200-400 行的建议区间.  更要紧的不是尺寸: 本项目至今出现的**全部真实缺陷都落在生命周期状态之间的交互上** —— 写时序 × close × 计时器.  两次"修 A 引入 B"都发生在这里 (严格 schema 改 passthrough 打穿了 error 载荷校验; 兜底计时器移进 write 回调制造了永久挂起).  这些状态目前挤在同一个类里, 彼此的边界只存在于阅读者的脑子里.

reviewer 在两轮 review 中都建议拆分, 并设了一个前置条件: **先建立真实的测试覆盖, 再拆**.  理由是"等价变换由测试全绿背书"这句话, 在唯一守着生命周期交互的测试是空转的情况下是空话.  该前置条件已在上一个 change 中满足 (真实内核背压 + 桩自证生效 + 双向变异验证, 并由独立 e2e 复现).  因此本轮做拆分.

同时补上两项联调前的准备: 与对端共享包的 schema 交叉校验, 以及把快照防护补完整.  这两项都不触碰实现.

## What Changes

**主线: 拆分 `src/bridge-client.ts` (纯等价变换)**

- 按两条生命周期切开: **连接生命周期** (connect / 握手与握手超时 / 关闭 / 两类计时器) 与**请求生命周期** (pending 表 / write 与写出确认 / 结算 / 按 id 归属)
- `src/framing.ts` 内聚良好, 本轮不动

**联调前准备 (不触碰实现)**

- 与 `@mie/tool-defs` 的 `./socket-protocol` 做**交叉校验**: 两边 schema 各跑同一组帧样本, 断言接受-拒绝判定一致, 使两份定义中任何一方先漂移都会立刻暴露
- 6 个 P0 tool 的 JSON Schema 快照**补锁 `description`** —— 目前只锁 `inputSchema`, 而对端改一句工具描述会直接改变 agent 的调用行为, 我们却零信号
- 把"**快照红了不自动更新, 必须报上来与对端对账**"这条规矩写进仓库.  它目前只活在口头约定里, 而快照的全部价值在于它是**对账触发器**而非同步工具 —— 一旦允许 `-u` 顺手带过, 这层防护立刻归零

## Capabilities

### New Capabilities
无.

### Modified Capabilities
- `bridge-transport`: 新增一条跨仓库一致性约束 —— 本侧对 socket 帧的接受/拒绝判定必须与共享包 `./socket-protocol` 的声明一致

**说明**: **拆分本身不改变任何 requirement**.  它是结构等价变换, 对外行为按定义与拆分前完全一致; 一个纯重构如果产生了 requirement 变更, 那恰恰说明它不纯.

唯一的 delta 来自交叉校验, 而它确实是一条**系统属性**而非测试手法: 本仓库与对端各自维护一份 socket 帧定义 (这是上一轮刻意的决策 —— 本侧校验经三轮打磨且有实测矩阵背书, 不切换到对端的 schema), 而"两份定义的判定必须一致"是这个决策成立的前提条件.  在此之前两份定义各自演进, 没有任何约束把它们绑在一起.

快照补锁 `description` 与"不自动更新"规矩不写成 requirement —— 它们描述的是我们如何守护既有 requirement, 属于测试与流程层面.

验收基准因此有两条: **既有 24 条 requirement 的全部行为在拆分前后完全一致** (由现有 89 个测试与既有 e2e 场景的全量回归背书), 以及新增的这条一致性约束成立.

## Impact

- 受影响代码: `src/bridge-client.ts` 拆分为若干模块; 既有测试文件的 import 路径可能随之调整 (**断言不得修改**); 新增交叉校验测试; 快照测试与快照文件更新; README 或快照文件旁新增规矩说明
- **不受影响**: 任何对外协议语义、错误码、提示文案、计时器起表时机、`src/framing.ts`
- 不需要提升 `protocol_version`
- 基线: commit `73cf4d5` (三个 change 已归档提交, 工作区干净, 89 tests 全绿).  等价性可用 `git diff 73cf4d5` 直接审阅
- 不在本次范围: `extractOversizedResponseId` 加括号深度扫描 (行为变化, 会破坏本轮等价性验证的判断力, 单独一轮做); 与真实 bridge / 真实 Chrome 的联调 (下一轮)
