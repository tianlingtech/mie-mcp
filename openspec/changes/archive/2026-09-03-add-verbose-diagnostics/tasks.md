## 6. 解码回调的同步性不变式

- [x] 6.1 把解码回调 (`onFrame` / `onOversizedResponse`) 的同步性纳入现有那条同步性 requirement 的覆盖 (spec 已写, 本组是确认实现与之相符)
- [x] 6.2a **解码器一侧的同步性以测试为证**: 两个回调是直接同步调用, 顺序测试 (before → callback → after) 经变异确认非空转 —— 把解码器改为 `queueMicrotask` 交付会使其失败
- [x] 6.2b **消费者一侧的回调不得为 async 属评审期约束, 不在测试覆盖内**: 注入的测试回调是同步的, 因此生产回调若改成 async, 顺序测试照样通过 (实测: 同步快照与全同步时完全一致, 而 `push()` 不同步抛出, 被拒 promise 会逃逸).  这条的主防线是 requirement 本身; 若要真正强制, 需要静态检查而非测试
- [x] 6.3 若发现实现实际上**不**满足, 停下来报告 —— 那是一个真缺陷而非注释问题
